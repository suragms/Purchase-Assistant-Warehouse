## Provider behavior and safety

- Provider adapters use fixed provider endpoints, JSON request/response handling, request cancellation and generic normalized failure responses. They do not log request prompts, provider response bodies, API keys or exception detail.
- Routing uses ordered sequential failover. It does not perform same-provider retries. The request-wide 45-second cancellation deadline bounds the parse flow; there is no provider-specific retry/backoff or circuit breaker.
- Missing tenant credentials use configured server fallback. If both are missing, the provider is marked unconfigured and skipped; no HTTP request is sent. `StubAIProvider` always returns failure and never creates a fabricated candidate.
- Invalid keys, provider quota/rate limits, provider timeout, malformed upstream JSON and unavailable model all become a generic provider failure and may trigger the next configured provider. Automated mocks cover error handling, not provider account acceptance.
- Business keys are protected at rest with ASP.NET Data Protection scoped to BusinessId and credential type. A stable shared production key ring is a deployment requirement so values can be decrypted across restarts/instances.
- AI purchase context is constructed only after server authorization and uses current-business supplier/catalog service results. The parser does not receive purchase-write or stock-write dependencies.
- The UI communicates review responsibility and now displays the server-side preparation timestamp. Model output never sets prices, totals, stock or purchase lifecycle state.

## Verification boundary

Automated tests with local HTTP handlers and fakes validate request construction, key routing, missing-key handling, failover and normalized errors. They do not prove DNS/TLS reachability, account validity, model availability, provider billing/quota, latency or actual output quality. Those checks require a non-production provider key and approved staging data flow; no credentials were available in this work. See `EXTERNAL_AI_OCR_VERIFICATION.md`.
